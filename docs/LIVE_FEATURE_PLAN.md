# biliTv 直播功能调研与设计方案

状态：需求设计稿，待确认后进入完整功能实现。本文覆盖一个完整直播功能包，不自行拆成多个发布阶段。

## 目标

让用户在 Shield 等 Android TV 设备上，仅用遥控器即可发现 B 站直播、进入直播间、观看实时弹幕、切换画质与线路、回到原来的频道和焦点。整体沿用 biliTv 现有的深色 Netflix 风格、悬浮顶栏、封面卡片与横向轨道，不另造一套视觉语言。

## 同类客户端观察

| 参考项目 | 值得借鉴的能力 | 对 biliTv 的启发 |
|---|---|---|
| [newBV](https://github.com/Frost819/newBV/)（最接近的 Android TV B 站客户端） | 直播推荐、分区、关注、排行榜；直播 HLS/FLV、多线路、WebSocket 弹幕、人气；同一 Media3 播放体系覆盖点播与直播 | 直播不能只有“输入房间号播放”；需要首页发现、分区浏览、关注回看及直播专用播放器状态 |
| [纯粹直播 TV](https://github.com/liuchuancong/pure_live_TV)（跨平台 TV 直播应用） | D-pad 优先；OK 呼出底部控制栏；索引式焦点管理；收藏、刷新、弹幕设置、清晰度、线路、切台、历史/推荐/搜索 | 直播控件必须按 TV 遥控器设计，焦点和视觉选中状态要可预测；直播播放时不应显示点播进度条 |

这些项目的功能描述来自当前公开仓库 README；它们适合作为交互参考，不代表 B 站接口稳定性或特定设备兼容性已经由我们验证。

## 现有工程基础与缺口

当前 app 已有悬浮导航、频道/首页轨道、12 条批次追加和焦点位置记忆、扫码登录、UP 主关注、观看历史、统一深色 UI、Media3 播放器、主备线路恢复、弹幕渲染和详细弹幕设置。这些可以复用。

目前仍缺少直播房间模型和 API、直播推荐/分区/关注列表、直播 WebSocket 消息连接、直播房间播放器状态（无 seek、有实时人气/下播状态）、直播收藏/历史，以及独立的直播画质和编码偏好。现有点播弹幕按视频时间轴调度，不能直接拿来驱动实时弹幕；渲染设置可复用，但消息队列和时钟需要适配直播。

## API 调研结论

目前可查到的 B 站直播接口主要由社区持续维护的逆向文档和客户端源码记录，未发现可作为长期兼容承诺的公开官方 API 文档。因此接入前应以当轮真实响应做接口契约验证，并在客户端保留错误分级、有限回退和可诊断信息；不能把单个端点视为永久有效。

- 首页推荐：`xlive/web-interface/v1/webMain/getMoreRecList`，社区文档记录返回直播封面、标题、主播、分区和人气等字段。[接口字段与示例](https://github.com/pskdje/bilibili-API-collect/blob/main/docs/live/recommend.md)
- 直播分区：`room/v1/Area/getList` 提供父/子分区；`room/v3/area/getRoomList` 按分区分页拉取房间。[分区接口说明](https://github.com/MayIHaveK/bili-apis/blob/master/docs/live/live_area.md)
- 房间解析与状态：`room/v1/Room/room_init` 可将短房间号归一为真实 room id；`room/v1/Room/get_info` / `xlive/web-room/v1/index/getRoomBaseInfo` 可查开播状态、标题、封面、主播与在线人数。[房间信息接口](https://github.com/dfh3913/bilibili-api-collect-mirror/blob/master/docs/live/info.md)
- 播放地址：`xlive/web-room/v2/index/getRoomPlayInfo` 返回服务端实际可用的清晰度、协议、封装、编码和多条 CDN URL。社区文档记录的参数包含 HLS/HTTP stream、FLV/TS/fMP4、AVC/HEVC，清晰度列表必须以响应为准。[播放信息接口](https://github.com/pskdje/bilibili-API-collect/blob/main/docs/live/info.md)
- 实时弹幕：`xlive/web-room/v1/index/getDanmuInfo` 返回 WebSocket 地址与 token；连接需要认证包、心跳和 B 站二进制消息解包。近期社区实现仍在更新该流程，需针对当前 WBI/凭据要求验证，并处理 token 过期、断线重连。[WebSocket 协议研究](https://github.com/streetartist/BiliKit/blob/main/Bilibili-Live-API-master/API.WebSocket.md)
- 直播搜索：已有搜索体系记录 `search_type=live`，返回直播间/主播结果；应沿用 app 的 WBI 签名和 Cookie 管理，并保留接口失败提示。[搜索类型说明](https://github.com/LittleYang0531/bilibili-API-collect/blob/master/docs/search/search_request.md)
- 播放器：Media3 官方支持常规 HLS 直播，但需要与当前 Media3 版本一致的 `media3-exoplayer-hls` 依赖；Media3 也列出 FLV 渐进式容器支持，不过直播地址类型、封装、编码和电视硬解仍须按样本实际验证。[Media3 HLS 指南](https://developer.android.com/media/media3/exoplayer/hls) [Media3 格式支持表](https://developer.android.com/media/media3/exoplayer/supported-formats)

排行榜/热门列表的页面和接口变动频率较高。本方案将“榜单”作为用户入口，但具体排序端点在实现前必须先实测；若榜单接口失效，不伪造热度排序，显示明确错误并保留“推荐/分区”入口。

## 产品与页面方案

### 1. 一级入口与直播首页

在顶部悬浮导航中新增固定「直播」入口（紧邻「首页」），搜索、我的、历史仍保持固定；直播不塞入会被横向滚动隐藏的普通频道列表。

直播页顶部为轻量二级切换：

- **推荐**：首屏精选/热门房间，后续按当前 API 可用数据组织为推荐、游戏、娱乐等横向轨道；每张卡片显示直播封面、LIVE 标记、人气、标题、主播和分区。
- **分区**：先展示父分区，再进入子分区房间网格/轨道；不把几十个子分区一次挤进顶栏。父/子分区都有醒目的“全部”和返回路径。
- **关注**：展示关注主播的直播状态和开播房间；未登录时显示扫码登录引导，不阻挡推荐/分区浏览。支持进入主播主页或直接进房。
- **榜单**：展示经验证的热门/分区榜单，提供刷新与分页；若接口被风控或不可用，明确提示并可退回对应分区。

卡片及轨道沿用首页实现：轨道独立记忆焦点和滚动位置；首卡左键刷新、末卡右键加载下一批；分页节奏固定每批 12 个，追加时不重绑旧卡、不刷新已缓存封面。网格/轨道使用首页布局偏好，直播页也可以尊重全局展示样式。

### 2. 搜索、收藏和历史

- 复用现有搜索页，增加「视频 / 直播」切换；直播结果可直接进房，并标记当前开播状态。搜索直播间与搜索主播先复用同一 `live` 搜索类型，按接口实际响应解析。
- 播放器有明确的收藏/关注操作：登录后关注/取消关注同步到 B 站；另提供本地收藏，避免登录要求让电视用户无法整理房间。
- 新增本地「直播历史」，记录最近看过的房间、观看时间及房间当时标题/主播。直播没有可恢复的时间进度，不显示“续播进度”；回看动作是重新进入当前直播间。
- 从直播播放器返回时恢复进入前的直播子页、分区、纵向滚动和焦点卡片；从“我的”或搜索打开的直播也返回原位置。

### 3. 直播播放器

使用独立 `LivePlayerActivity`，复用现有播放器的 Surface、线路诊断、全屏底色、自动隐藏控制层、弹幕设置和焦点高亮；不把直播强塞入点播 Activity，以免 seek/分 P/历史续播状态彼此污染。

播放器默认全屏沉浸；首帧后控制层淡出。按确定键显示控制层，再按确定键切换播放/暂停（暂停是本地停播，不提供点播进度）；返回键先关闭面板/控制层，第二次返回才退回直播列表。

控制层按遥控器使用频率从左到右排列：**返回直播列表、弹幕开关、画质、线路、刷新流、关注/收藏、房间信息**。当前选中项用高对比度描边和填充同时表达，面板淡出后焦点回到视频画面。播放画面上常驻轻量主播头像/标题/分区与实时人气，数秒后收为不遮挡画面的角标。

- 直播没有时间轴：隐藏点播进度条、快进预览、倍速和分 P；左右键在控制层隐藏时可切换当前列表前/后一个房间，显示控制层时只移动按钮焦点。
- **清晰度**只展示接口实际返回且设备可播放的档位。默认“自动 · 最高兼容”；能力判断沿用当前设备运行时解码器探测，不硬编码 Shield。实验性高规格只作为显式选择，不参与自动档。
- **编码**放在独立直播设置：自动优先 AVC/H.264，再使用设备支持的 HEVC/H.265；指定编码时不静默跨编码回退。直播 API 当前常见格式由实际响应确认，不展示服务端没有返回的 AV1 选项。
- **线路**显示“主线路 / 备用线路 1 / 备用线路 2”，连接错误或超时后有限次数自动切线，全部失败再刷新播放地址；手动选线沿用当前网络线路体验。仅在新流成功出首帧后才更新选中状态。
- **协议/封装**优先 HLS（Media3 HLS 模块），其次验证可用的 HTTP-FLV/TS/fMP4；同一线路内按 API 实际响应组装 URL。若选定流在设备上不兼容，回退同编码的其他协议/线路，最后提示用户降低清晰度或切换自动编码。
- 房间下播或被限制时显示“直播已结束/当前房间不可播放”状态，停止重复重试，并可返回推荐列表或刷新房间状态。

### 4. 实时弹幕

在现有 `DanmakuOverlay` 基础上复用字号、速度、覆盖范围、不透明度、密度等设置，但直播弹幕使用独立实时输入管线：WebSocket 接收 → 心跳/协议解包 → 有界队列 → 现有优化过的绘制层。直播弹幕按到达时间调度，不依赖媒体 position；切房立即清空旧房间消息，避免串房。

增加直播弹幕连接状态（连接中/已连接/重连中/暂不可用）及开关明显态。断线采用有上限的退避重连；用户关闭弹幕时应释放/暂停连接策略，退出房间时必须关闭 socket、心跳和队列。直播弹幕默认不显示礼物动画等复杂消息，只渲染可读文本及有限的用户色彩，避免电视上过度遮挡。

本功能包建议先覆盖**观看弹幕**，暂不做发弹幕、礼物、舰长/付费互动：这些都涉及登录态、风控、输入法或付费确认，且不属于“看直播”的必要路径，可避免遥控器操作误触。

### 5. 设置

新增独立「直播」设置分类：

- 直播首页展示：轨道/网格（默认跟随首页）、榜单入口显示、推荐轨道开关/排序（如果推荐接口提供稳定分组）。
- 默认直播清晰度：自动兼容、原画、蓝光、超清等仅展示的服务端选项；实际可用项以房间动态返回为准。
- 默认直播编码：自动 / H.264 / H.265；实验性高规格沿用通用设备能力规则。
- 默认协议：自动（默认）、优先 HLS、优先 HTTP-FLV；自动模式按设备支持、流响应和连通性选择。
- 自动切换线路、弹幕默认开关；弹幕样式复用当前全局详细设置。
- 本地直播历史/收藏清理入口。

设置页继续使用当前横屏左右分栏，直播选项放入自己的 sheet 分类，避免继续把所有项堆在单页。

## 技术实现边界建议

- 数据层增加 typed `LiveRoom`、`LiveArea`、`LiveStreamSet`、`LiveDanmakuMessage` 模型和 `LiveRepository`；所有接口、响应兼容、room id 规范化及 Cookie/WBI 策略留在 data 层。
- UI 使用独立直播首页状态与播放器 Activity；公共视频卡片可抽取封面/标题/焦点能力，但不直接复用带视频观看进度语义的 `VideoCard`。
- 使用当前 `AppExecutors`/异步模式，禁止网络和 WebSocket 解包占主线程。流 URL、token、Cookie 不写日志或持久化。
- 复用线路自动恢复与网络诊断的分类原则，区分 API 限流、房间下播、URL 过期、CDN 网络错误、解码不支持。
- 收藏和历史本地保存；B 站关注列表按登录账户读取，账户切换时清理/隔离用户数据。

## 完整交付验收范围

1. 顶栏入口、推荐/分区/关注/榜单、搜索直播、遥控器刷新/分页/焦点记忆完整可用。
2. 未登录用户可看公开推荐与可看直播；关注等账号能力有清晰登录引导。
3. 播放器能解析实时房间号、正确播放有效直播流；设备支持过滤、画质/编码/线路切换、自动恢复、下播错误态可用。
4. 直播弹幕可稳定连接、绘制和断线恢复；切房/退出资源释放，不串房，不让弹幕拖慢视频帧率。
5. 直播历史/收藏/关注入口与返回焦点行为稳定；设置独立分类持久化。
6. 覆盖 Shield Android 11/API 30 真实设备或等价硬件回归；模拟器验证 UI/焦点和公开测试流，但模拟器解码能力不能代替 Shield 的实播验证。

## 建议确认的默认边界

我建议按本文作为一个完整功能包实施：包含推荐、分区、关注、榜单、搜索、本地历史/收藏、直播播放器、实时弹幕观看、画质/编码/线路选择和独立直播设置；先不包含发弹幕、礼物、投屏、录制、直播回放。确认后再进入代码实现；如果希望缩小或增加边界，我们先修订此稿，不在实现中途自行拆分。
