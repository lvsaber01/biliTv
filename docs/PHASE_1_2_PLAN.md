# 第一、二阶段功能落地方案

## 目标

在现有深色 TV 轨道和遥控器焦点模型上，补齐最影响日常使用的播放器交互和登录后内容管理能力。实现以 Bilibili 当前接口为准，接口失败时保留基础播放和本机进度，不让增强功能阻断主流程。

## 第一阶段：播放器与遥控器体验

### 1. 预览定位

- 通过 `/x/player/videoshot` 获取视频快照时间表和雪碧图地址。
- 只有用户第一次进入定位预览时才请求快照，避免所有视频播放都额外下载图片。
- 左右键只修改目标时间，画面显示缩略图、目标时间和相对偏移。
- 松开方向键、按确认键或 1 秒无输入时只提交一次 seek。
- 快照请求失败时仍保留时间预览和普通 seek，不影响播放。

### 2. 字幕、章节和显示模式

- 复用 `/x/player/wbi/v2` 的字幕和 `view_points` 数据。
- 字幕 JSON 在本地解析成时间轴，由轻量覆盖层显示，避免把不稳定的字幕 URL 直接交给播放器。
- 播放器快捷栏提供字幕开关、字幕轨道选择、章节跳转和画面比例。
- 字幕覆盖层只显示当前时间段，生命周期跟随播放器，返回页面不产生后台任务。
- 画面比例支持适应、铺满、裁剪三种模式，并保存为全局播放偏好。

### 3. 播放线路诊断

- 第一版先展示当前播放格式、视频/音频 URL 的 CDN 主机和最近一次错误。
- 保留现有备用地址和低画质回退，不在没有实测收益前增加复杂测速请求。
- 下一轮再根据 Shield 实机网络结果决定是否开放线路选择和测速。

## 第二阶段：内容管理

### 1. 稍后再看

- 使用 `/x/v2/history/toview` 读取列表。
- 详情页增加“稍后再看”，账号页增加独立入口。
- 稍后再看卡片直接续播，沿用本机进度和云端进度合并规则。
- 删除操作在下一小版本补入，避免第一版误删；先确保读取和添加稳定。

### 2. 收藏操作

- 使用 `/x/v3/fav/folder/created/list-all` 获取收藏夹，并以 `fav_state` 初始化多选状态。
- 使用 `/x/v3/fav/resource/deal` 一次提交新增和移除的收藏夹。
- 未登录、CSRF 失效或接口被风控时显示可理解的错误，不修改本地收藏状态。

### 3. UP 主空间与关注关系

本项作为一个完整功能包实施，不拆分为先页面后关系的中间版本：

- 视频详情作者区进入 UP 主空间；头部统一沿用 biliTv 深色面板、头像、认证、简介和统计信息。
- 主页支持最新投稿/最多播放切换、投稿视频网格、增量分页、卡片续播进度和返回焦点恢复。
- 登录后显示关注/已关注状态，支持关注和带二次确认的取消关注；未登录操作进入二维码登录。
- “我的”增加关注列表入口，列表展示头像、简介、直播状态和已关注标记，可进入同一 UP 主空间。
- 投稿请求采用 WBI 空间接口、旧空间接口和 `recArchivesByKeywords` 兼容回退；其中最后一层用于应对 WBI 风控和 `-799` 限流。
- 动态流、粉丝管理、关注分组和评论互动不属于本次 UP 主空间范围，避免在没有确认交互方案前扩大功能边界。

### 3. 播放队列

- 先沉淀“播放全部/连续播放”的队列模型和入口位置。
- 队列切换必须复用现有详情、进度和画质选择流程，不能直接拼接未经详情确认的播放地址。
- 在播放器增强功能稳定后接入自动下一条，避免把网络错误和队列状态混在首版改动中。

## 验收标准

- 没有快照、字幕或章节数据时，视频仍能正常播放。
- TV 遥控器左右定位不会误触发设置按钮，确认键只提交一次跳转。
- 详情页新增操作不会破坏返回、继续播放、分 P 和焦点位置。
- 收藏和稍后再看不在日志、普通设置或未加密存储中暴露 Cookie/CSRF。
- 单元测试覆盖快照索引裁剪、字幕/章节解析、收藏请求参数、稍后再看解析和 TV 定位状态机。
- 单元测试覆盖 UP 主资料、关系状态、投稿字段和分页解析；TV 回归覆盖作者入口、主页排序、关注登录引导和我的关注入口。
