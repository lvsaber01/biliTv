# 播放画质与设备兼容策略

## 目标

播放器不再把 1080P 作为固定上限。Bilibili 返回的实际 DASH 轨道是可选能力的来源，客户端根据运行时检测到的 Android 解码器、HDR 显示能力和帧率能力过滤选项。显示输出模式不再直接作为解码上限，避免 Shield 的当前 HDMI 输出模式误把 1080p/4K 隐藏。这样同一份 APK 可以安装在 Shield、普通 Android TV 盒子、电视和 Android 平板上，而不需要把某一款设备写死在代码里。

## 服务端能力

播放请求优先使用 `/x/player/wbi/playurl`，失败后回退旧 playurl 接口。DASH 请求使用完整能力声明，并解析返回的 `dash.video`、`support_formats` 和轨道元数据。

支持识别的画质包括：

- 360P、480P、720P、720P60
- 1080P、1080P+、1080P60
- 4K、HDR、Dolby Vision、8K
- AVC/H.264、HEVC/H.265 和 AV1 编码

服务端返回的轨道仍受登录状态、会员权限、视频本身、地区、风控和 CDN 策略影响。客户端不会因为请求了高规格能力就伪造不存在的轨道，也不会把只有名称没有实际 URL 的元数据展示为可播放选项。

## 本机能力检测

`PlaybackDeviceCapabilities` 在启动播放前通过 `MediaCodecList` 检测解码器的 MIME 类型、最大宽高和最大帧率，并通过 Android `Display.HdrCapabilities` 检测 HDR10、HLG、HDR10+ 和 Dolby Vision 显示能力。过滤规则包含：

1. 轨道宽高不得超过对应解码器能力。
2. 轨道帧率不得超过对应解码器能力。
3. 轨道编码必须有可用解码器；软件 AV1 解码器不作为 Android TV 的可靠 AV1 能力。实际 DASH 轨道仍按单独的 codec 选择。
4. HDR 和 Dolby Vision 还必须有匹配的显示能力。
5. 当系统不能提供有效探测结果时，不武断拒绝服务端轨道；普通选项仍按服务端实际返回展示。

这里的检测只负责“默认可用性”判断，不能替代真实播放。厂商固件、外接显示器、HDMI 链路和播放器解码路径可能使实际结果与系统声明不同。

## 设置与交互

播放设置提供四个默认画质策略：

- 自动 · 最高兼容：选择当前设备判断可播放的最高规格，默认值。
- 最高 1080P：限制自动选择不超过 1080P。
- 最高 4K：允许自动选择到 4K。
- 最高 8K：允许自动选择到服务端提供的最高档位，但仍遵守本机能力过滤。

另有“实验性高规格播放”开关，默认关闭。开启后，在设置中指定某个编码时，播放页的分辨率选择器会把本机判断为不确定或不支持、但服务端确实返回 URL 的轨道标记为“实验性”，允许用户手动尝试；自动编码模式仍只使用已验证的轨道，不会因为实验性开关打开就自动选择 AV1。

播放页只选择分辨率，不展示编码变体。编码在设置中统一配置：自动模式在同一目标分辨率内按 H.264 → H.265 → AV1，指定编码后没有对应轨道就停止并提示切换编码或分辨率，不跨编码静默回退。

如果实验性轨道黑屏、无法解码或加载失败，错误面板提供“重试”和“切换低一级”。切换低一级优先选择当前画质以下的兼容轨道，并保留当前播放位置。播放页切换画质同样保留位置和播放/暂停状态。

## 设备兼容边界

TV 模拟器可以验证设置、筛选逻辑、焦点和错误回退，但无法模拟 Shield 的 Tegra 解码器、HDR/Dolby Vision 输出、HDMI 链路或真实遥控器。2019 圆筒 Shield TV 的 4K/HDR 支持需要在实机确认；8K 不应被视为该设备的目标能力。

当设备检测结果与实际表现不一致时，建议按以下顺序操作：

1. 保持“自动 · 最高兼容”，先确认普通轨道可播放。
2. 在设置中指定要尝试的编码，再打开“实验性高规格播放”，在播放页手动选择带“实验性”标记的高规格分辨率。
3. 如果出现黑屏或解码错误，使用错误面板“切换低一级”，或关闭实验性开关。
