# biliTv 需求分析与实施流程

## 目的

后续功能优化不直接从一句需求进入编码。对于会影响首页结构、播放流程、数据接口、设置项或用户操作习惯的需求，先完成需求分析、方案比较和范围确认，再开始实施。

这份流程是项目的长期协作约定，用于减少“功能做出来了，但配套设置、异常状态或业务入口没有覆盖”的情况。

## 什么时候需要中断确认

以下情况默认进入需求分析并和用户确认：

- 新增一个页面、频道、内容类型或核心业务流程。
- 改变首页、播放器、登录、收藏、历史等既有主流程。
- 需求涉及多个入口，例如首页展示同时需要设置页、导航栏或播放页配套。
- 需求需要新增或替换 Bilibili API，存在接口失效、登录要求、风控、分页或字段兼容风险。
- 需求会影响遥控器焦点、触摸手势、横竖屏、平板和 Android TV 等多个交互环境。
- 需求存在多种合理实现，且会影响数据模型、持久化设置、性能或后续扩展。

以下低风险事项可以直接处理：

- 明确的编译错误、崩溃修复和不改变行为的兼容性修复。
- 已确认设计范围内的视觉细节、文案、间距、颜色和无争议的代码重构。
- 用户已经明确给出实现方案，且不存在额外业务分歧。

## 需求分析输出

进入实施前，先向用户给出一份简短但完整的评估，至少包括：

1. 当前项目中相关功能、代码入口和已知限制。
2. 需求目标、用户场景和不包含的范围。
3. 现有实现与目标之间的差距。
4. 业务布局和交互流程，包括触摸、遥控器焦点、加载、刷新、空状态和错误状态。
5. 是否需要设置项、导航入口、数据持久化或默认值。
6. API、登录、风控、分页、字段兼容、网络消耗和缓存风险。
7. 至少一个推荐方案，以及必要时的备选方案和取舍。
8. 可验证的验收标准、测试范围和预计版本变更。

复杂功能可以分多轮讨论。只要范围、默认行为或关键取舍仍然存在歧义，就先暂停实施并询问；不会把“用户可能也需要”的扩展功能默默加入本次开发。

## 确认门槛

开始编码前，需要确认以下内容：

- 本次版本要实现的功能清单。
- 默认行为和用户可配置项。
- 页面入口、交互方式和异常状态。
- API 方案和不可用时的回退策略。
- 明确不做的内容。
- 验收标准。

用户确认后，只实施已确认范围。如果开发过程中发现必须扩大范围、改变默认行为或新增外部依赖，先说明影响并重新确认。

## 频道轨道需求的标准检查项

以首页增加 Bilibili 分区轨道为例，不能只检查“是否显示了更多轨道”，还要一起评估：

- 轨道列表：默认包含哪些频道，是否允许启用/隐藏。
- 轨道排序：是否支持拖动排序、预设排序或恢复默认排序。
- 展示策略：每条轨道的卡片数量、横向追加方式、是否显示 Hero、空轨道如何处理。
- 更新策略：手动刷新、下拉/横向滑动触发、自动刷新频率和重复内容去重。
- 设置页面：轨道开关、排序入口、刷新策略、移动网络下的行为。
- 交互兼容：平板触摸滑动、Android TV 遥控器左右键、焦点保持、加载中和错误状态。
- 数据接口：分区 `rid` 映射、分页能力、接口回退、登录要求、限流和请求并发。
- 持久化：设置保存位置、默认值、接口更新后旧设置如何兼容。
- 验收标准：首次加载、刷新、滑到末尾、隐藏轨道、改变顺序、断网和接口失败等场景。

## 推荐的需求记录格式

每个中大型功能可以在 `docs/` 下增加一份设计记录，使用以下结构：

```markdown
# 功能名称

## 背景与目标

## 当前状态与问题

## 本次范围

## 不在范围内

## 用户流程与页面布局

## 设置项与默认值

## API、缓存与失败回退

## 方案与取舍

## 验收标准

## 实施记录

## 版本与变更记录
```

## 实施后的闭环

确认后的实施按以下顺序完成：

1. 更新数据模型、API 网关和设置模型。
2. 更新页面布局与交互状态。
3. 用真实或可复现的接口响应验证关键路径。
4. 运行 assemble、单元测试和 lint；涉及 TV 界面、焦点或播放流程时，先在本地 TV 模拟器做相关回归，再交付给用户进行 Shield 真机补验，详见 [TV 测试环境](TV_TEST_LAB.md)。不能将 JVM Android 测试等同于实际设备验收，未执行项目明确标为待验。
5. 更新 README、CHANGELOG 和必要的功能设计记录。
6. 使用清晰的 Git 提交说明和版本号记录变更。
7. 向用户汇报已完成范围、未完成范围、验证结果和下一步选项。

## 本次经验的处理结论

当前分区轨道已经完成了首页展示、刷新和自动追加，但“轨道排序、隐藏、刷新策略等设置”尚未纳入实现范围。后续如果继续完善该功能，应先根据本流程完成一轮需求确认，再进入设置页和数据持久化改造。
