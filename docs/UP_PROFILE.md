# UP 主空间与关注关系

## 目标

在 biliTv 现有深色悬浮导航、轨道卡片和 TV 遥控器焦点模型上，补齐从视频到作者的连续浏览路径。页面重点不是复制移动端个人空间，而是让用户在沙发距离下快速判断“是谁、值不值得关注、还有什么视频可看”。

## 页面结构

```text
视频详情
└── 作者区「UP主 名称」
    └── UP 主空间
        ├── 返回 / 刷新
        ├── 身份头部
        │   ├── 圆形头像
        │   ├── 名称、认证、等级、直播状态
        │   ├── 关注 / 粉丝 / 投稿统计
        │   ├── 两行简介
        │   └── 关注 / 已关注
        ├── 最新投稿 / 最多播放
        └── 投稿视频网格

我的
└── 我的关注
    └── UP 主网格
        └── 头像、名称、简介、直播状态、已关注
```

头部和排序栏固定在网格上方，避免滚动到下一页后丢失关注操作；投稿网格沿用首页卡片、封面缓存和本机观看进度。主页默认聚焦首张投稿卡片，向上依次回到排序栏和关注按钮；详情返回时恢复作者入口焦点。

## 关注交互

- 未登录点击“＋关注”：进入已有二维码登录页，不伪造本地关注状态。
- 已登录点击“＋关注”：请求成功后变为“已关注”，粉丝数本地加一。
- 已关注点击“已关注”：先弹出确认，再请求取消关注；失败时保留原状态。
- 关注状态在打开主页时通过关系接口读取，避免使用上次页面残留状态。
- 关注列表只读展示 B 站当前关注关系，点击卡片进入同一 UP 主空间；后续取消关注由 UP 主空间统一完成。

## 接口与回退

| 用途 | 首选 | 回退 |
| --- | --- | --- |
| 用户资料 | `GET /x/space/wbi/acc/info` | `GET /x/web-interface/card` |
| 关系统计 | `GET /x/relation/stat` | 资料中的 `fans/attention` |
| 投稿数量 | `GET /x/space/navnum` | 资料缺省为 0 |
| 投稿视频 | `GET /x/space/wbi/arc/search` | 旧空间投稿接口 → `GET /x/series/recArchivesByKeywords` |
| 关系状态 | `GET /x/relation` | 未登录显示未关注并引导登录 |
| 关注/取消关注 | `POST /x/relation/modify` | 失败时不更新 UI 状态 |
| 我的关注 | `GET /x/relation/followings` | 登录失效显示明确错误 |

用户资料和投稿接口集中在 `BiliApiClient`，UI 不拼接 URL。投稿回退使用 `pubdate` 或 `views` 排序，适配 WBI 风控和匿名/登录场景的差异。

## 当前边界

本次完整功能包包含 UP 主主页、投稿浏览、关注/取消关注和我的关注列表；不擅自加入动态流、粉丝管理、关注分组、评论互动或直播间聊天。这些功能需要另行完成需求分析和交互确认后再进入实施。
